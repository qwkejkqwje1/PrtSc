# PrtSc 0.8 architecture

Rust Windows x64, OS DLLs only. `windows-sys` provides window/graphics/shell/hotkey APIs; windows projection provides WinRT OCR/Media Foundation. Internal Luma class/crate names retained for compatibility, not product names.

- Editor model retains annotations independent of the selection. Internal Select is invoked when no area exists or a pointer starts outside it. Eight edge bits are hit-tested before drawing and resize only the selection, not annotation coordinates. Cancelled border drags restore the old region. Pen is startup default. Undo/redo remains annotation-based; selection resize is not an annotation-undo entry.
- Edge layout has a 36×428 drawing rail (11 tools + color/width/undo/redo), 328×36 action rail (10 buttons); Compact is 448×76. Independent surfaces avoid an enormous union bitmap and false canvas hitboxes. Old docking settings are ignored/migrated; neither style uses screen-side overrides. Badge uses 5×7 pixel glyphs at 2× scale in a 22px-high surface. Edge placement considers viewport and badge.
- Scene cache holds raw flattened annotations without UI/dim. Chrome caches its actual small surfaces; tool-colors are included in the cache key. Drawing tools use their own saved stroke colors on their icons; neutral active background and blue border avoid losing the icon against identical blue fill.
- QR worker decodes only the final image locally. Auto-QR is revision-tagged/debounced. Explicit QR copies in place; background results do not close/open dialogs. A separate UI-only hit-tested result row inside the selection, placed near the QR action, has two distinct targets: HTTP(S) text opens the validated URL and closes the editor after successful ShellExecute dispatch, a separate 28px overlapping-pages button copies full values. Non-URL text also copies. QR indication is on the QR button only. UI-only result text never enters screenshot exports.
- A read-only EDIT subclass records physical key combinations and handles registered WM_HOTKEY events without invoking capture while focused; Tab navigates, Escape restores the persisted binding. A focus-scoped WH_KEYBOARD_LL hook captures only VK_SNAPSHOT (including release-only events), suppressing OS screenshot action only while editing; it unhooks on focus loss/destruction, with direct Snapshot KEYUP fallback. Global capture key is parsed into RegisterHotKey modifiers/VK values. Settings reserve an alternate registration ID before saving; conflicts preserve the old binding, save failure unregisters the candidate, successful save swaps then unregisters the old ID. Ctrl+Shift+R is separate recording hotkey. Stale ID messages are ignored.
- Capture uses top-down 32-bit DIB. For video only, optional GetCursorInfo/GetIconInfo/DrawIconEx adds the visible current cursor using hotspot and screen-region offsets. DeleteObject frees returned mask/color bitmaps; GdiFlush synchronizes the DIB before reading. Cursor is composited before optional GIF scaling. If a foreign cursor handle cannot be inspected, a standard-arrow fallback preserves its position/motion. Ordinary screenshot capture excludes the cursor. NV12 conversion remains top-down for MP4.
- Google returns one single-use HTML response with base64-embedded encoded pixels. Browser builds a File/DataTransfer multipart and posts directly to Lens; no fetch/second local image request. Encoder runs concurrently with GUI-thread ShellExecuteW browser dispatch. Loopback binds random port/token and validates Host/Origin/path; no referrer/cache/files. Up to 32 incomplete sockets are multiplexed nonblockingly with bounded headers and 2s expiry; speculative browser preconnections cannot block a real request; server lifetime is45s and runs only after explicit user action. Metrics measure local preparation/dispatch, not Google processing.
- Saved-file reveal uses COM/SHParseDisplayName and SHOpenFolderAndSelectItems(filePIDL,0,...), not keyboard automation. Native notification/Explorer reuse acceptance remains open; see QA. Hosting, WinRT OCR, PrintWindow and MF retain documented runtime/acceptance limitations.

- Original tiger SVG assets generate a multi-resolution PNG ICO. Optical 16/20px variants preserve contrast. EXE resource ID1 feeds window/tray icons; embedded ICO fallback supports runtime loading. Node/sharp generator is build-time artwork tooling only, not an app dependency.
